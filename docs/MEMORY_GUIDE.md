# MEMORY_GUIDE.md - 記憶の使い方

## エージェントが保持すべき記憶構造

本ガイドは、AIエージェントが本システムを継続的に運用する際に、
セッションをまたいで参照すべき記憶（メモリ）の構造を定義する。

## 1. 永続記憶（システム知識）

これらは常に記憶しておくべき：

```
システム構成:
  - Python + Streamlit + SQLite
  - yfinance（株価・米国株財務）+ edinet（日本株財務・テキスト）
  - sec-edgar-api（米国株決算書テキスト）
  - FinBERT（感情分析）

データ蓄積戦略:
  - 株価: 初回全期間、以降差分のみ
  - 財務: 毎回取得、古いデータは削除せず追加

センチメントDLルール:
  - 1回50銘柄ずつ
  - 同一銘柄は24時間以上あける
  - DLログを確認してから実行
```

## 2. セッション記憶（運用状態）

各セッション開始時に確認すべき情報：

```
# 前回までの進捗
- DL済み銘柄数 / 全銘柄数
- センチメントDLの最終実行日時
- バックテストの前回実行日

# エラー状況
- error_log に未解決のエラーがないか
- 連続失敗している銘柄がないか

# データの鮮度
- prices の最終更新日
- financials の最終更新日
- tickers の最終更新日
```

## 3. 記憶テンプレート

```
# ========================================
# システム状態 スナップショット
# 作成日時: YYYY-MM-DD HH:mm
# ========================================

## データ状況
- 全銘柄数: 12,000
- DL済み株価銘柄数: 12,000
- DL済み財務データ銘柄数: 8,500（日本株はedinet残り）
- センチメントDL進捗: 1,200/12,000（XX%）
- DBサイズ: XXX MB

## 最終更新日
- 株価: YYYY-MM-DD
- 財務: YYYY-MM-DD
- センチメント: YYYY-MM-DD（最新50銘柄）
- 銘柄リスト: YYYY-MM-DD

## 直近のエラー（要対応）
- ticker_id=1234: 3回連続エラー
- ticker_id=5678: 銘柄廃止の可能性

## 次回アクション計画
1. □ 株価差分更新
2. □ センチメントDL 次の50銘柄
3. □ バックテスト実行（前回から更新あり）
```

## 4. 気づき・発見の記録ルール

以下のパターンに気づいたら記録する：

| 気づき | 記録内容 |
|--------|---------|
| 特定ルールのスコア偏り | 「Valueルールが金融株に常に高スコア」 |
| データ欠損パターン | 「edinetでXX業種のデータが取得できない」 |
| パフォーマンス問題 | 「全銘柄バックテストにXX分かかる」 |
| API制限パターン | 「NewsAPIがYY時に必ず切れる」 |
| 改善提案 | 「ZZルールの計算式をこう変更すると精度が上がる」 |

## 5. ルール追加時の記憶

新ルール追加時は以下を記録：
```
新ルール名: [名前]
作成日: YYYY-MM-DD
計算式: [簡略な説明]
必要データ: [株価/財務/テキスト]
初回バックテスト結果: [TOP3銘柄スコア]
備考: [特記事項]
```
